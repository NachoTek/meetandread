## Summary

Move the test suite out of GitHub Actions and run it locally; GitHub's only job becomes building the release bundle (PyInstaller).

Raised by the maintainer during #64 triage, parked there as a follow-up.

## Current state (gathered 2026-08-24)

Three workflows run the full test suite on `windows-latest` hosted runners:

| Workflow | Trigger | What it does |
|---|---|---|
| `test.yml` ("Tests") | nightly cron + push/PR to main | lint + full suite (35 min) |
| `build-validation.yml` ("Build Validation") | push/PR to main | lint + full suite, then PyInstaller build validation |
| `release.yml` ("Release") | tags `v*` | lint + full suite, then release build + attach |

All three duplicate the same pytest invocation (and all three carried the now-removed `--ignore=tests/test_settings_history.py`).

## Motivation

- Hosted runners are slow (~33-35 min vs. targeted local runs) and hardware-limited (no mic input — see the `skip_no_mic` guard added in #70; loopback tests already skip there).
- The local Windows VM already runs the authoritative full suite (ADR-0001 topology), and the `.githooks/pre-push` hook already gates every push on it — so GitHub-hosted tests are largely redundant with local gating.
- Hosted-runner flakes burn 30+ min per retry (e.g. the 5s `Event.wait` timeout fixed in #70).

## Open design questions (to resolve in triage)

1. **Reporting** — if tests run locally, what is the source of truth for "this SHA passed"? Options: commit-status/check posted from the VM, a lightweight local CI runner reporting to GitHub, or trust the pre-push hook + no status check.
2. **pr-review.yml coupling** — its `workflow_run` trigger fires on Build Validation completion and webhooks Hermes on failure. Moving tests out changes or breaks that trigger; needs a redesign.
3. **Branch protection** — if main currently requires status checks, they'd be removed or replaced.
4. **Scope of the GitHub job** — keep only the PyInstaller bundle (build-validation + release), presumably still on `windows-latest` for a clean build environment.
5. **Nightly cadence** — does the VM run the nightly full suite instead (cron/`test.yml` dropped)?
