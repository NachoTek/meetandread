## Agent Brief

**Category:** enhancement
**Summary:** Make GitHub Actions green and consolidate CI: PR + nightly + release testing, deterministic hardware-free tests, fixed bundle validation, label-gated agent review.

**Current behavior:**

- Three workflows each duplicate the same ~34-min test suite on `windows-latest`, including redundant push-triggered runs.
- The nightly "Tests" workflow has failed 9+ consecutive nights: `test_rebuild_mic_source` fails on GitHub runners with `AudioSourceError: No microphone input devices found` despite a `skipif(not list_mic_inputs())` guard — device *enumeration* succeeds on the runner, then *opening* the device fails. Guard checks the wrong layer, so it's nondeterministic across runs of the same commit.
- The PyInstaller bundle validation has failed on every run since 2026-07-31 with "✗ Missing SVG icons": the SVG and performance-test-data checks glob a hardcoded `dist/meetandread/meetandread/...` path, but PyInstaller 6.x places datas under `dist/meetandread/_internal/...`. CI installs PyInstaller unpinned, so a runner-side version bump silently changed the layout. The DLL checks pass because they search recursively.
- `pr-review.yml` webhooks Hermes only when Build Validation *fails* — wrong trigger for review, and coupled to a workflow that is being reshaped.

**Desired behavior:**

1. **Consolidated CI.** Exactly one definition of the lint+test job (a reusable/workflow-call job is the natural mechanism), used by:
   - PRs to `main`: lint + full suite + PyInstaller bundle validation + artifact upload.
   - Nightly schedule on `main`: lint + full suite (safety net).
   - `v*` tags: lint + full suite, then release build + attach to the GitHub release.
   - No `push:` triggers anywhere. `milestone/**` filters removed.
2. **Hardware-free mic test.** `test_rebuild_mic_source` must pass deterministically on machines with no openable microphone: mock the device layer the source constructor reads (the test asserts the controller builds the right source wrapper for `type="mic"` — it does not need real hardware). Keep real-hardware coverage only under an explicit hardware-guarded marker that skips when no mic can actually be *opened* (probe by opening, not enumerating).
3. **Deterministic bundle validation.** Data-file checks (SVG icons, performance test data) must locate files the same way the DLL checks do — recursive search from the bundle root, tolerant of `_internal/` relocation. Pin the PyInstaller version in CI (and ideally a constraints file) so future layout changes are a deliberate upgrade, not a silent break.
4. **Label-gated agent review.** Replace the `workflow_run`-failure trigger: when the `ready-for-codereview` label is added to a PR, send the same HMAC-signed webhook (same secret, same Hermes endpoint, same payload shape incl. PR number) so the review agent engages. No webhook on unlabeled/failed runs.

**Key interfaces:**

- Workflow trigger blocks (`on:`) — the contract being changed; no `push:` allowed.
- The reusable test job — single source of truth; PR/nightly/release all call it.
- Mic device layer: `list_mic_inputs()` (enumeration) vs the device-open path in the mic source constructor — the guard must move from enumeration to open-probe or be mocked out entirely for the unit test.
- `validate_build.py` data-file checks — switch from fixed paths to recursive glob, mirroring `check_required_dlls()`.
- `pr-review.yml` webhook payload — unchanged shape; only the trigger becomes `pull_request: [labeled]` filtered on `ready-for-codereview`.

**Acceptance criteria:**

- [ ] No workflow in the repo triggers on push to `main` or `milestone/**` (grep the `on:` blocks).
- [ ] A PR to main produces exactly one full-suite run plus one bundle-validation run (no duplicated suites across workflows).
- [ ] Nightly suite on main passes 3 consecutive nights with zero mic-hardware failures.
- [ ] `test_rebuild_mic_source` (and its mocked variant) passes on a machine with no openable mic; a hardware variant exists and skips (not fails) there.
- [ ] Build Validation passes on a PR with the pinned PyInstaller, including SVG + test-data checks.
- [ ] Tagging a `v*` tag runs tests, then builds and attaches the release bundle.
- [ ] Adding `ready-for-codereview` to a test PR delivers the signed webhook (HTTP 200 visible in workflow logs); no webhook fires on CI failure alone.
