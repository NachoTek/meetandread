## Root cause

`soundfile` was removed from the project in 0.19.1 (replaced by stdlib
`wave`), but this slow-marked e2e test still did `import soundfile` at
module-test scope (line 88). The test sits outside the pre-push gate
(`-m "not slow"`), so pushes stayed green while genuine full-suite runs
failed with `ModuleNotFoundError: No module named 'soundfile'`.

## Findings

- Verified red before the fix: `ModuleNotFoundError` at
  `tests/test_speaker_pipeline.py:88` (run 2026-08-29, exact failure captured).
- Fix: read the synthetic WAV with the app's shared
  `load_wav_as_float32_mono()` (`src/meetandread/audio/utils.py`) instead
  of `sf.read(...)`. That loader always returns 16 kHz float32 mono, so
  `sr = 16000` afterwards is correct by contract (resample happens
  internally; `sd.sample_rate` is 16 kHz for these models).
- Verified green after: target test passes (11.2s);
  `tests/test_speaker_pipeline.py` 71/71 pass (26.4s);
  fast suite (`-m "not slow"`) no regressions.

## Code review (off-path work, /code-review on branch diff)
